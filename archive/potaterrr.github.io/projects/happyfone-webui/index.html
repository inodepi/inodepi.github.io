What it is

HappyFone WebUI is the prototype of the softphone I'm building for HappyPhone. It is a production-style agent console with no framework and no dependencies — plain HTML, CSS and ES modules, deployed on GitHub Pages.

The point was to make the caller's day concrete before wiring real telephony: where they sign in, how they go available, what happens between calls, and what they see when one ends.

What's inside

  • Mock auth and a session guard: username, extension, password; direct dashboard visits bounce back to sign-in
  • Agent state machine — AVAILABLE, ON_CALL, WRAP_UP, AUX — with a live timer
  • AUX reasons (lunch, short break, bio, coaching, training) that pause the dialer until the agent returns
  • Simulated call lifecycle: ringing, connected timer, mute, hold/resume and hangup
  • Keyboard-first dialing, including T9 letter mapping and DTMF tones while connected
  • A five-second wrap-up countdown, then back to available
  • Persistent call history that survives reloads, with click-to-dial
  • Responsive dark UI with accessible focus states and reduced-motion support

What is still simulated

Auth is mocked and calls are simulated — there is no real audio path yet. The production softphone is the one I'm building at happyphone.lol/caller: real JWT auth, a Kamailio + RTPEngine gateway, and calls through the team's VoIP.ms sub-account.
